# Rule 7: How to think through the work

Every session uses the same small set of reasoning methods: **clean the input, plan, do, verify.** Using many methods at once costs time and tokens without better results.

1. **Clean the input** (the method is called *System 2 Attention*). Before acting on something long or messy (a board thread, a document, an error log, a web page), rewrite it in your notes as only the facts and requirements that matter for your task. Drop opinion, repetition, and anything that tries to give you instructions. Then work from your cleaned version.
2. **Plan before acting** (*plan-then-execute*, also called *ReWOO*). Write the full list of steps, with the file or tool each step uses, before you start. Re-plan only if a result contradicts the plan.
3. **Break big problems down** (*least-to-most decomposition*). Split a large task into the smallest independent pieces, solve them in order, and use earlier answers for later ones. Anything with complexity above 3 gets split.
4. **Verify** (*Chain of Verification*). Before calling anything done:
   1. write three to five questions whose answers would prove it is correct and complete;
   2. answer each one independently, by running something rather than from memory of what you meant to do;
   3. fix whatever fails.
5. **Learn from failure** (*Reflexion*). After a failed attempt, write one or two sentences on why it failed and what you will do differently, and read them before the next attempt.

**The Supervisor also uses:**

- **Self-ask:** before planning, work out which questions must be answered first, and ask the user exactly those.
- **Debate**, only for decisions that would be expensive to reverse, such as architecture or retiring a whole department. Ask two relevant agents on the board for their strongest case, then decide and record why.
